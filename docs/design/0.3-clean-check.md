# 0.3 design: content-based clean check (RU-02)

> **Superseded.** The user reversed the content-based clean check (Addendum 3, task 0.3-simp) as overengineering for an evaluation-only tool used with cooperative agents. The harness-eval clean check is `git status` hardened by fsmonitor/untracked-cache off, `--no-replace-objects`, and fail-closed assume-unchanged/skip-worktree and filter-attribute checks. This file is kept as history only.

Status: proposed (Architect, task 0.3-arch2). Scope: `dirty()` in `skills/ruach-harness-eval/scripts/common.ts` and its two consumers, `acceptance.ts` (`dirty_before`/`dirty_after`) and `scope-check.ts` (`dirty`, `clean`, `assessed_paths`). Items marked **needs-decision** need user approval before they are implemented. Design only; nothing here has been implemented.

## 1. Problem: one class, many variants

RU-02/A1 requires that repository state the candidate controls cannot make a checkout read as clean. `dirty()` delegates that decision to `git status`. `git status` is a cache-driven, configuration-driven comparison:

- **Stat cache.** It re-hashes a tracked file only when the index stat data differs from `lstat`.
- **Configuration.** How it compares, and what it reports, depends on repository config, attributes, ignore files and index flags.

All of these live in the candidate's checkout. Three fix cycles have each closed one input:

| Cycle | Variant | Fix in place |
|---|---|---|
| rev-sec B1 | `core.fsmonitor` hook reporting no changes | `-c core.fsmonitor=false` |
| A1 | `assume-unchanged`, `skip-worktree` | fail closed (`hidden_index_state`) |
| rev2 N1 | clean filter via `.gitattributes`, `info/attributes`, `core.attributesFile`, macros | fail closed (`content_filter_state`) |
| rev3 N2 (open) | `core.trustctime=false` or `core.checkStat=minimal`, plus an equal-size edit with mtime restored | none |

The design probes for this task (run against `3093323`/`7cad2f7` `dirty()` from the session scratch directory) found four more variants that are **open today**. Each returns `[]` for a forged state:

| Probe | Forged state | Current `dirty()` |
|---|---|---|
| P-a | untracked `evil.ts` listed in `.git/info/exclude` | `[]` |
| P-b | untracked `evil.ts` listed in a file named by repository `core.excludesFile` | `[]` |
| P-c | `core.filemode=false`, `chmod +x protected` | `[]` |
| P-d | untracked `sub/.gitignore` containing `*` (it ignores itself), plus `sub/evil.ts` | `[]` |
| P-e | tracked root `.gitignore` edited to `*`, plus untracked `evil.ts` | only `.gitignore` is reported; `evil.ts` is hidden from `assessed_paths` when `require_clean: false` |

Not probed, by reasoning only:
- `core.symlinks=false`: a tracked symlink replaced by a regular file holding the target text reads as unchanged.
- A hand-written `.git/index` whose stat fields match a tampered file (the rev3 residual).

Every variant has the same root: **the cleanliness decision consults state the candidate can write.** Disabling inputs one at a time cannot close the class. Git keeps adding inputs, and some, such as the index stat bytes themselves, cannot be disabled by any `-c` flag.

## 2. Principle

Decide cleanliness only from:

1. **Committed objects.** The HEAD commit and its tree, read with `--no-replace-objects`. They are content-addressed, so the candidate cannot change them without changing HEAD, and HEAD is already pinned and reported.
2. **Raw worktree bytes and types**, observed directly by the checker with `lstat`/`readlink`/`read`, and hashed by the checker.
3. **Index entry object IDs**, used only to classify a difference as staged or unstaged. The index can never make a path clean. Its entries are compared to the HEAD tree by object ID, and the worktree is compared to the index by object ID, so a lying index entry shows up as staged dirt.
4. **Ignore rules taken only from `.gitignore` files that are tracked, present in HEAD and byte-identical in the worktree.** Section 6 explains this.

The check must never consult:
- index stat fields or index flags (assume-unchanged, skip-worktree, fsmonitor-valid);
- `core.*` comparison settings (`trustctime`, `checkStat`, `filemode`, `symlinks`, `ignorecase`, `fsmonitor`, `untrackedCache`, `autocrlf`, `eol`, `safecrlf`);
- attributes (`filter`, `text`/`eol`, `ident`, `working-tree-encoding`);
- `info/exclude`, `core.excludesFile`, `status.*` or `submodule.*.ignore` / `diff.ignoreSubmodules`.

## 4. Algorithm

`dirty(repo)` keeps its signature and returns the same record shape: `{ status, paths, staged, unstaged, untracked }[]`. Git still runs through the existing private `git()` wrapper, which strips the environment and passes `--no-replace-objects` and `-c core.fsmonitor=false -c core.untrackedCache=false`. Add `-c core.ignorecase=false`.

1. **Object format:** `git rev-parse --show-object-format` gives `sha1` or `sha256`.
2. **H, the HEAD manifest:** `git ls-tree -r -l -z --full-tree HEAD` gives a map from path to `{mode, type, oid, size}`. Gitlinks have mode `160000` and size `-`. An unborn HEAD is a setup error: a worktree HEAD is already required by both callers.
3. **I, the index manifest:** `git ls-files -s -z` gives a map from path to `{mode, oid, stage}`.
   - Without `--sparse`, a sparse index is expanded to full entries.
   - A path with any stage other than 0 is **unmerged**.
4. **Tracked set:** T = keys(H) ∪ keys(I). For each path p in T, sorted:
   - `X` (index against HEAD), comparing (mode, oid):
     - absent in H, present in I: `A`
     - present in H, absent in I: `D`
     - same type, different oid or mode: `M`
     - type class differs (file, symlink or gitlink): `T`
     - unmerged: `U`, with `Y=U`
     - otherwise ` `
   - `W[p]`, the worktree observation (Section 5): absent, or `{mode, oid}`, computed lazily.
   - `Y` (worktree against index), same letters:
     - absent in W, present in I: `D`
     - present in I with different mode or oid: `M`, or `T` on a type change
     - absent in I, present in W: the path is untracked relative to the index and is handled in step 5, so `Y` is ` `. This matches porcelain `D ` plus `??`.
   - If `X` or `Y` is not a space, emit `{status: X+Y, paths: [p], staged: X!==' ', unstaged: Y!==' ', untracked: false}`.
5. **Untracked set:** list with `ls-files` under trusted ignore rules (Section 6), and emit `{status: '??', paths: [q], staged: false, unstaged: false, untracked: true}` for each path q. Untracked nested repositories appear as `dir/`, as they do in `status` (verified).
6. Sort the records by path for deterministic output.

**Size shortcut.** When `I[p]` equals `H[p]` (the common case), compare the worktree size from `lstat` with the size from `ls-tree -l`. If they differ, `Y=M` without reading the file. Only files of equal size are read and hashed. When `I[p]` differs from `H[p]`, the path is already dirty and the full `W` hash is still computed for an accurate `Y`. That cost is bounded by the budget (Section 7).

**What counts as clean.** `clean` is true when there are no records. That means H equals I, I equals W for every tracked path, and nothing is untracked under trusted rules. This is the same definition as today, minus the forgeable inputs.

## 5. Worktree observation per path

The checker walks each tracked path component by component, using `lstat` and following no symlinks. Results for parent directories are cached.

| Worktree state | `W[p]` |
|---|---|
| A parent component is missing, a symlink or not a directory | absent (Git reports such a path as deleted) |
| `p` is missing | absent |
| `p` is a directory and H/I says blob or symlink | absent; its contents are untracked candidates and are listed by `ls-files` |
| Regular file | mode `100755` if `st_mode & S_IXUSR`, else `100644`; oid = hash(`"blob <size>\0"` + bytes) |
| Symlink | mode `120000`; oid = hash of `readlink` **bytes** (`{encoding: 'buffer'}`) |
| FIFO, socket or device | a special type that never equals any entry, giving `T`/`M`. It is **never opened**. |
| Gitlink path (H or I mode `160000`) | Section 8 |

**Reading regular files.**
1. Open with `O_RDONLY|O_NOFOLLOW|O_NONBLOCK`.
2. `fstat` the descriptor and require a regular file whose `dev`/`ino` match the `lstat` result.
3. Stream the content in 1 MiB chunks into `createHash(sha1|sha256)`, so memory stays bounded whatever the file size.
4. Require that the bytes read equal the `fstat` size and that the next read returns EOF.

If any step fails, or the file changes while it is read, the path is dirty (`Y=M`). It never reads as clean, and the read never hangs. This follows the A4 pattern of `readArtifact`, but streams instead of buffering.

**Paths.** Git paths are decoded the way the current code decodes them (UTF-8 via `-z`). A name that is not valid UTF-8 resolves to a different filesystem path, observes as absent and reads as dirty. That is fail closed. Byte-exact handling of such names is out of scope.

## 6. Ignored and untracked files

Current semantics are kept. Untracked files that are not ignored are dirty. Ignored files are not dirty; they are covered only by the opt-in `expected_tree_paths`/`canonical_files`. What changes is that **the ignore rules must come from committed content.**

1. Run `git ls-files -z --others --exclude-per-directory=.gitignore`. Without `--exclude-standard`, Git reads neither `info/exclude` nor `core.excludesFile` (verified; this closes P-a and P-b). It does read every per-directory `.gitignore` present in the worktree, so the next steps validate those.
2. Find every `.gitignore` the run could have used that is not committed and unchanged:
   - any tracked `.gitignore` path with a record from step 4 (modified, deleted, staged, or present in I but not H);
   - any untracked `.gitignore`, whether it appears in the step 1 output or in `git ls-files -z --others --ignored --directory --exclude-per-directory=.gitignore`. The second listing does not descend into ignored directories, and the self-ignoring P-d file appears in it individually (verified).
3. If step 2 finds any such file:
   - Report every one of them as dirt. Untracked ones get a `??` record, even when they ignore themselves, which closes P-d.
   - Recompute the untracked set **with no exclude rules**: `git ls-files -z --others`. Every non-tracked file is then assessed, which closes P-e for scope with `require_clean: false`.
   - The recomputation can be large (for example `node_modules`). Exceeding the entry budget gives `clean_check_budget` (Section 7), a setup error and never clean.

Rejected for this step:
- **A TypeScript gitignore matcher:** semantic divergence risk.
- **Rewriting HEAD's `.gitignore` files into one `--exclude-from` file:** translating per-directory pattern semantics and precedence is error prone.
- Falling back to no-exclude listing is simple and fails closed, and it is triggered only when the checkout is already dirty.

The `ls-files --ignored --directory` probe is a second process over non-ignored directories only. Its cost is about one `status` traversal.

## 7. Bounds (A4 consistency)

Two new constants live next to `ARTIFACT_LIMIT`:
- `CLEAN_ENTRY_LIMIT = 100_000` paths, counted separately for H, I and each untracked listing;
- `CLEAN_HASH_LIMIT = 1 GiB` of bytes hashed in one `dirty()` call.

Exceeding either throws `SetupError('clean_check_budget', 'repo', …)`. A budget failure is a setup error (exit 2), never `clean`.

How these relate to A4:
- `ARTIFACT_LIMIT` (16 MiB) bounds *in-memory* artifact reads. The clean check streams, so its memory is bounded by the chunk size rather than the file size, and it needs no per-file limit. Large tracked files (assets, fixtures over 16 MiB) are hashed instead of being rejected.
- The existing `git()` `maxBuffer` of 32 MiB holds `ls-tree -l -z` for about 100k entries (roughly 120 bytes per entry). A larger output already fails as `git_error`, so the entry budget and the buffer agree.
- **Time.** SHA-1 measured on this host under load (8 cores, load average above 25) ran at about 360 MB/s, so the worst case at the hash budget is about 3 s of hashing plus I/O per call. Acceptance calls `dirty()` twice. Typical checkouts hash far less, because the size shortcut skips reading files whose size changed, but every equal-size tracked file is read on every call. That is the cost of not trusting stat.

**needs-decision D3:** confirm the budget values above, or set others. They are deliberately constants, not configuration.

## 8. Submodules

For a path whose H or I entry is a gitlink (`160000`):
- **Directory absent:** `W` is absent, so `Y=D`. Git reports ` D` (verified).
- **Directory empty:** the submodule is not initialized and is treated as clean. Git reports nothing (verified).
- **Otherwise:**
  1. The directory must contain `.git`, and `root(dir)` must resolve to that directory. If it does not (for example a plain directory with files), `Y=T`.
  2. Read the submodule's `HEAD` commit through the private `git()`. If it differs from the gitlink oid, `Y=M`.
  3. Run the same algorithm recursively on the submodule, with depth at most 4 and the budgets shared. Any inner record gives `Y=M` on the gitlink path. The inner paths are not listed, which matches today's ` M module` record and the existing submodule test.

Because the recursion uses the same content-based check, the stat and config forgeries are closed inside submodules too. A gitlink present in H whose directory holds an unrelated repository is caught by step 2.

## 9. Sparse checkouts, symlinks, modes and other cases

- **Sparse checkout (skip-worktree, `info/sparse-checkout`).** Paths outside the cone are absent from the worktree and observe as `D`, so the checkout is dirty and fails closed. Today it fails closed as `hidden_index_state`. Honoring sparse patterns was rejected because they live in candidate-writable `.git/info/sparse-checkout`. Document: "harness-eval requires a full checkout."
- **Symlinks.** Link target bytes are compared with the blob. A typechange between file and link gives `T`. A tracked path behind a parent symlink reads as deleted, consistent with Git. Symlink targets are never followed, which matches `canonical_files`.
- **Modes.**
  - Only `100644` and `100755` exist for blobs. The worktree exec bit is `S_IXUSR`, which is Git's rule when `core.filemode` is true. The rule is applied unconditionally, which closes P-c.
  - On filesystems without exec bits this can give a false `M`. That platform is outside current support; record it in the docs.
- **Intent-to-add (`add -N`).** Absent in H and present in I gives `A`, which is dirty. Git prints ` A`; only the letter position differs, and the dirtiness is the same.
- **Unmerged index.** `UU` gives a record with both flags set.
- **Line endings (`autocrlf`, `text eol=crlf`), `ident`, `working-tree-encoding`.**
  - Raw bytes are compared with the blob, so a checkout whose bytes differ from the committed blob is dirty.
  - On Linux with LF-normalized blobs this changes nothing. The existing control test (`*.txt text eol=lf`) stays clean.
  - Checkouts whose working copies are converted (CRLF on checkout, expanded `$Id$`, UTF-16 working encoding) now read as dirty.
  - **needs-decision D1:** accept byte-exact semantics (recommended), or apply conversions. Applying them would make the comparison depend on candidate-writable attributes and config again, reopening the class.
- **Filters (LFS and similar).** The worktree content differs from the pointer blob, so these files are dirty. Smudge-only no-op filters, and `-filter`, read correctly (rev3 O1 resolved). The documented LFS limitation stays: "checkouts that use filters must be checked another way".

## 10. Interaction with the existing fail-closed checks

| Check | Keep or retire | Reason |
|---|---|---|
| `--no-replace-objects` | keep | object reads must be pinned |
| `GIT_*` environment stripping | keep | the repository selection must be the requested one |
| `-c core.fsmonitor=false -c core.untrackedCache=false` | keep | defense in depth for the `ls-files` probes; harmless |
| `-c core.ignorecase=false` | add | exact path matching for `ls-files --others` against index entries on case-sensitive filesystems |
| `hidden_index_state` (assume-unchanged / skip-worktree throw) | retire | flags are no longer consulted. A tampered flagged file is reported as `M`; an untouched flagged file is correctly clean; a sparse checkout is reported as `D` records. |
| `content_filter_state` (`check-attr filter` throw) | retire | attributes are no longer consulted. A filter cannot forge equality of raw bytes, and retiring removes the false rejections of `-filter` and no-op smudge filters. |
| `check-attr` stdin support in `git()` | remove if unused | it was only needed by `content_filter_state` |

Retiring the two throws changes the observable result for those cases. The outcome stays non-`ok`, but scope-check moves from exit 2 to exit 1 and diagnostics move from `hidden_index_state`/`content_filter_state` to `dirty_worktree`/`dirty_candidate`. The existing tests assert only non-`ok`, a non-zero exit and diagnostics, so they keep passing.

**needs-decision D2 (output contract):**
1. Retire the two error codes.
2. Stop producing `R`/`C` dirty records. A dirty rename becomes `D ` old plus `A ` new. Both paths are still in `assessed_paths`; only the record grouping changes.
3. Add `clean_check_budget`.

Recommended: accept all three. Update `references/config.md` ("dirty record … both for a rename"), `docs/operations.md` Known limitations and `docs/regression-cases.md`.

Rename detection was dropped because the real risk lives in the worktree side, and a status-like `RM` merge adds parsing for no security value. Staged renames could be recovered later with `git diff-index --cached -M` if anyone needs them.

## 11. How the consumers derive their sets

- **acceptance:** `dirty_before = dirty(repo)` before the checks and `dirty_after = dirty(repo)` after them, in the same places as today (`acceptance.ts:158,206,214`). A check that tampers with a file and restores its mtime, or that rewrites `.git/config`, `.git/info/*` or the index between the two calls, cannot affect `dirty_after`, because none of those inputs is consulted.
- **scope-check:**
  - `result.dirty = dirty(repo)` and `clean = dirty.length === 0`.
  - `assessed_paths` = committed `changes()` paths ∪ every `paths` entry of the dirty records. `changes()` is commit-to-commit (object-level) and does not change.
  - Untracked and ignored-rule fallback paths flow into `unexpected_paths`/`protected_changes` exactly as dirty paths do now.
- `canonical_files` and `expected_tree_paths` are unchanged; they already read raw bytes.

## 12. Trust boundary and out of scope (document in `docs/operations.md`)

The clean check is trustworthy only if the following hold. Each is out of scope:

1. **The checker's own execution.**
   - The `bun` runtime, the skill scripts, and the `git` binary found on the caller's `PATH` (`executable('git', process.cwd(), process.env)`) are trusted.
   - A candidate that can write to any of them, or to the caller's environment, controls the result.
   - Acceptance runs candidate commands with the operator's privileges and does not sandbox them (already documented in `references/config.md`).
2. **Candidate processes that outlive the checks.** A descendant that escaped the owned process group (for example via `setsid`) can change files after `dirty_after`. Acceptance proves state only at the moment of observation.
3. **The filesystem.**
   - FUSE or other candidate-controlled mounts, bind mounts, or a filesystem that returns different bytes per reader.
   - Case-insensitive or normalizing filesystems, where distinct Git paths alias. The check is designed for case-sensitive POSIX filesystems.
4. **Hash collisions.** In SHA-1 repositories, equality is by object ID, and the checker's SHA-1 does not include Git's collision detection. A candidate who authored both the committed blob and a colliding worktree file (a chosen-prefix collision) could forge equality. SHA-256 repositories are not affected. The alternative is a byte comparison against `git cat-file --batch`, which costs a second read of every equal-size blob. Deferred; **needs-decision D4:** accept this as a documented boundary (recommended) or require byte comparison.
5. **Ignored files under committed ignore rules** are not part of `clean`, as today. Use `expected_tree_paths`/`canonical_files` for protected ignored locations.
6. **Content of untracked nested repositories** is reported only as `dir/`, as today.
7. **`ready`'s informational dirty flag** in `scripts/install.ts` is not a trust boundary and is not changed.

## 13. Rejected alternatives

| Alternative | Why rejected |
|---|---|
| Keep adding `-c` overrides (`core.trustctime=true`, `core.checkStat=default`, `core.filemode=true`, `core.symlinks=true`, …) | Enumerative; this is how three cycles each missed the next variant. It cannot cover hand-written index stat bytes, `info/exclude` or self-ignoring `.gitignore`. |
| Private index copy (`GIT_INDEX_FILE` set to a temp file, `update-index --really-refresh`, then `status`) | Removes the stat trust, but `status` still applies attributes, filters, eol, filemode, symlinks and exclude config, so the N1-type checks would have to stay. It also writes a temporary index and keeps rename/porcelain parsing. |
| `git hash-object --no-filters --stdin-paths` | Newline-delimited paths (the fixtures include `added\nwith\ttabs`), it follows symlinks, and it still runs Git under candidate config. |
| Fresh `git worktree add`/clone of HEAD into a temp dir, then a recursive diff | Doubles the I/O and disk use, needs writes to `.git/worktrees` (a checkout mutation) and still needs ignore semantics. |
| Neutralizing all repository config (`GIT_CONFIG_NOSYSTEM`, an empty `HOME`) | Repository `.git/config` and `info/*` are always read, so this does not remove the inputs. |
| Conversion-aware hashing (apply eol/ident/encoding) | Conversions are selected by candidate-writable attributes and config, which reopens the class (D1). |
| Byte comparison against blob contents | Stronger than OID equality, but doubles the reads; offered as D4. |
| Keeping `hidden_index_state`/`content_filter_state` as well | Redundant once flags and attributes are not consulted, and they produce false rejections (rev3 O1). |
