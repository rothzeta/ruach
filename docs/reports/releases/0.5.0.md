# Ruach 0.5.0: Pi and Goose harness preparation

Pi v1.4+ within major 1 now prepares native workers instead of returning `unsupported_adapter`. The adapter requires an exact `provider/model` entry in the native offline catalog, maps explicit effort to thinking levels, adds canonical skills individually and appends the canonical role through a private native extension. The extension preserves Pi's composed system prompt, including native `APPEND_SYSTEM.md` and ambient project instructions.

Goose v1.56+ within major 1 is registered for direct and routed selection. Its adapter prepares `session --provider ... --model ... --system ...` with the canonical role and an on-demand canonical skill index. Native settings, hints, extensions and skill discovery remain active. Effort must be omitted or `auto`, and both adapters require inherited permissions. No native pass-through arguments or auto-review mapping are enabled.

The inspected Herdr 0.9.0 advertises Pi and omits Goose. Goose offline routing and native adapter preparation are covered, while live resolve, dry-run and startup fail `unsupported_herdr_kind` before resource creation until upstream Herdr supports Goose. No alternate kind or raw-pane launch is used. Ambient workflow descriptions can remain visible; only the Coordinator may load workflow bodies. Goose system instructions are redacted in launcher output but visible in native process arguments.
