# Capability behavior cases

Static raw-input packets for later isolated evaluations of C1/C3/C4/C5. No subject runs, native capability proof or real-product demonstration is recorded here. All fixture projects, event histories and logs are synthetic. Packet authoring and source checks cannot close behavioral acceptance.

No executable preparation utility is needed: these are small immutable briefs and raw files copied into a consumer-allocated temporary workspace. There is no packet runtime or new test runner. The debugging fixture is a TypeScript source template, not a committed executable or a test of prose. Existing root resource checks validate links/notices; later evaluations grade actual decisions and observable behavior.

## Give and withhold

Select one case and one control, copy only its subject brief and named raw inputs, then fill real workspace/build/role/resource identities and authority. Keep pristine input and actual outputs separate; record source digests and actual rendered assignment. Coordinator subjects receive only their selected workflow and role. Workers receive only their technical skill, installed role and self-contained brief. Do not give a worker orchestration bodies.

Withhold this README, grader directory, other cases/controls, solved examples, plans, prior reports/transcripts and evaluator conclusions. A full repository/plugin cache can expose them; omission from a prompt is not exclusion. Inventory effective discovery/access surfaces, establish positive task/skill access and negative harmless grader-marker access under the actual session before claiming blind answer access. Council additionally needs peer-answer exclusion during open rounds. Preserve failed controls.

Record assistance (`assisted`, `unassisted`) separately from answer access (`blind`, `non-blind`, `unverified`), with actual evidence/interventions. Skill-hinted briefs are assisted; they may still be blind. Unknown access remains unverified. A restricted copy differing from the native route is a separate experiment.
