# Agy additive preparation

Use for an authorized non-Coordinator worker. Current preparation supports exactly Agy 1.4.7. Earlier 1.4.6/1.2.x evidence does not establish this interface; changed native versions need new capability evidence. No route fallback occurs.

## Native contract and gates

The adapter verifies installed `--model` / `--add-dir` help on stdout or stderr and exact version, then reads `agy models` without inference. The selected slug must equal a catalog entry, not a substring/fuzzy match. Catalog inspection can initialize native runtime state and uses the caller's native account/configuration. It is not a model turn or entitlement proof. Raw help/catalog contents are withheld from launcher diagnostics.

Only inherited native permissions are supported. `auto-review` has no verified mapping and is rejected, not downgraded or translated to native bypass. Effort is omitted or `auto`: e.g. `gemini-3.8-flash-medium` is the exact selected model/effort slug, and no separate `--effort` flag is emitted. No native pass-through, `--agent`, print/prompt, resume, mode or trust flag is supplied. Coordinator is rejected before native inspection/materialization. Consumer routes and permission policy remain consumer-owned; Ruach's development wrapper explicitly maps this advisory selection to inherit without changing other harness policies.

## Private material

The existing Plan materializer creates a restricted per-launch directory:

```text
<private-temp>/.agents/rules/ruach-<role>.md
<private-temp>/.agents/skills/<canonical-technical-name> -> <canonical-source>
```

The rule has `trigger: always_on`, a native include referencing the absolute canonical role source and explicit source/skill/reference-resolution context. The source stays canonical; it is not copied, edited, truncated, used as a replacement system prompt or sent as later user task text. The initialized role and later self-contained assignment are separate. Existing native discovery, consumer rules, account roots, built-in skills and settings remain active. Only the generated root is added with literal `--add-dir` argv; supplied technical-skill links omit canonical workflows by declared skill name, including directory aliases.

Source and actual worker cwd each run preparation through the existing launcher. Role hash, literal argv/full-argv transport, named same-pane readiness, blocked input, uncertain retention and cleanup ownership remain in their existing implementation. Native trust dialogs require their applicable owner authority; nothing here answers them. Private roots/directories are 0700, generated rule data 0600. Retain material after active/uncertain/blocked launch until the Coordinator ends concrete reuse.

## Size and discovery limits

Installed customization guidance documents a **24,000-byte per-rule limit after include expansion**, with line-boundary truncation above it. The adapter conservatively counts canonical Markdown body plus wrapper/context against that limit and fails instead of shortening the role. Empty role bodies, unverified nested native includes and canonical source paths containing parentheses/backslashes that cannot be represented by the verified include grammar are held before mutation. Native body-frontmatter stripping was demonstrated for the accepted Scout fixture; it is not permission to alter source.

Canonical skill names must be unique. Different same-name skill sources in known workspace customization roots, global filesystem skill discovery or installed built-in directories fail rather than override existing customization. The same resolved canonical source can be deduplicated. This is a bounded filesystem check, not a replica of native discovery/config precedence: declared `skills.json`/plugins, account/custom discovery and changes after preparation remain unverified. They are never broadly disabled or silently claimed absent.

Native always-on/global rules also share a documented **20,000-token aggregate budget**. Aggregate native inlining is not established by the per-file byte guard; no unsupported tokenizer, effective-catalog API or private metadata/database reader is invented. Actual session validation must confirm the complete role remains inline and the intended skill source is available under the consumer's real rules/customizations. If the native budget demotes/truncates the role or precedence replaces the intended skill, that acceptance stays held. Preparation coverage is not universal native-role acceptance.

`hidden_workflows` is empty because the adapter does not claim native ambient workflow suppression. Supplied links omit workflow skills; canonical context forbids workers from loading workflow bodies. Existing ambient descriptions/catalogs and plugin/account visibility may differ. Council independence/exclusion cannot be inferred from an empty fixture or these links.

That one diagnostic did not perform skill activation or the intended literal-brief task; its accidental user input and bounded timeout remain separate evidence. A native generation-metadata wire path used by the evaluator is evidence extraction only, never a supported production interface.

Source/fake checks establish prepared files, literal argv, gates, second-cwd inspection and retention. A separately authorized real linked Herdr advisory must establish actual native role/permission/identity, preserved consumer context, full rule/skill source, controlled brief-path read, on-demand skill activation and useful advisory output.
